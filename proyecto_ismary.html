Modificadores de acceso y encapsulamiento de clases

Bienvenido Profesor Robyirt ;)

¿Qué es el encapsulamiento?

El encapsulamiento (u ocultamiento de información) consiste en agrupar los datos y los métodos que operan sobre ellos dentro de una misma clase, y restringir el acceso directo a sus componentes internos. Así se evita que el estado de un objeto sea modificado de forma incorrecta por código externo. El objeto expone una interfaz controlada, normalmente mediante propiedades o métodos públicos.

Analogía: en un automóvil, el motor y los pistones están ocultos bajo el capó. No los manejas directamente: usas el volante, los pedales y la llave.

¿Qué son los modificadores de acceso?

Son palabras clave que definen la visibilidad de clases, métodos, propiedades y otros miembros desde otras partes del código o de otros ensamblados (archivos .dll). Abre cada uno para ver su alcance.

public · Acceso sin límites

Se puede acceder desde cualquier parte del código, incluso desde otros proyectos o ensamblados.

private · Solo la propia clase

Ninguna otra clase, ni siquiera las derivadas, puede verlo ni modificarlo. Es el nivel por defecto de los miembros de una clase.

protected · La clase y sus derivadas

Accesible desde la clase contenedora y desde cualquier clase que herede de ella, incluso en otros ensamblados.

internal · Mismo proyecto

Accesible solo dentro del ensamblado actual. Otros proyectos externos no pueden usarlo.

protected internal · Proyecto o derivadas

Combina ambos: acceso desde el ensamblado actual o desde clases derivadas ubicadas en otro ensamblado.

private protected · Solo desde C# 7.2

Acceso únicamente dentro de la clase contenedora o de clases derivadas en el mismo ensamblado. No existe en C# 5; se menciona como evolución del lenguaje.

¿Para qué sirve el encapsulamiento?

Integridad de los datos

Evita valores inválidos, como una edad negativa o un saldo alterado sin validaciones.

Mantenimiento más fácil

Puedes mejorar el código interno de una clase sin romper el resto de la aplicación.

Uso más simple

Quien use tu clase solo ve lo que necesita, sin la complejidad que ocurre por dentro.

¿Para qué sirven los modificadores de acceso?

Son las herramientas con las que construyes el encapsulamiento: decides quién ve y usa cada parte.

public

Expone lo que otras partes del sistema o desarrolladores necesitan usar, como los botones de una máquina.

private

Blinda los datos sensibles y la lógica interna para evitar errores accidentales.

protected

Crea confianza dentro de una familia de clases: el padre comparte con sus hijas lo que oculta al resto.

internal

Protege el código a nivel de proyecto, visible entre archivos propios pero no para librerías externas.

Ejemplos

Ejercicio: sistema de cuenta bancaria digital. El saldo debe estar protegido de modificaciones directas; todo depósito o retiro debe pasar por validaciones de monto y fondos.

CuentaBancaria.cs
using System;

namespace ConsoleApplication26
{
    class Program
    {
        static void Main(string[] args)
        {
            CuentaBancaria miCuenta = new CuentaBancaria();

            miCuenta.Depositar(1000.00);
            miCuenta.Retirar(350.50);

            Console.WriteLine("El saldo actual en la cuenta es: $" + miCuenta.ObtenerSaldo());
            Console.ReadKey();
        }
    }

    class CuentaBancaria
    {
        // Privado: nadie fuera de esta clase puede alterarlo
        private double saldo = 0.0;

        public void Depositar(double monto)
        {
            if (monto > 0)
            {
                saldo += monto;
                Console.WriteLine("Depósito exitoso de: $" + monto);
            }
            else
            {
                Console.WriteLine("El monto a depositar debe ser mayor a cero.");
            }
        }

        public void Retirar(double monto)
        {
            if (monto > 0 && monto <= saldo)
            {
                saldo -= monto;
                Console.WriteLine("Retiro exitoso de: $" + monto);
            }
            else
            {
                Console.WriteLine("Fondos insuficientes o monto inválido.");
            }
        }

        public double ObtenerSaldo()
        {
            return saldo;
        }
    }
}

Ejercicio: estructura de datos de un sistema escolar con herencia, mostrando qué variables se exponen al programa principal (public), cuáles quedan ocultas (private) y cuáles se comparten solo con clases derivadas (protected).

Estudiante.cs
using System;

namespace ConsoleApplication26
{
    class Program
    {
        static void Main(string[] args)
        {
            Estudiante alumno = new Estudiante();

            // Público: se asigna directamente desde Main
            alumno.Nombre = "Alejandro";

            // Estas líneas darían error si se descomentan:
            // alumno.edad = 20;           // 'edad' es private
            // alumno.calificacion = 19;   // 'calificacion' es protected

            alumno.MostrarDatos();
            Console.ReadKey();
        }
    }

    class Persona
    {
        // Protegido: visible en esta clase y en las que heredan de ella
        protected double calificacion = 18.5;
    }

    class Estudiante : Persona
    {
        // Público: accesible desde cualquier lugar
        public string Nombre;

        // Privado: solo dentro de Estudiante
        private int edad = 21;

        public void MostrarDatos()
        {
            Console.WriteLine("--- DATOS DEL ESTUDIANTE ---");
            Console.WriteLine("Nombre (Público): " + Nombre);
            Console.WriteLine("Edad (Privado, accedido internamente): " + edad);
            Console.WriteLine("Calificación (Protegido por herencia): " + calificacion);
        }
    }
}
